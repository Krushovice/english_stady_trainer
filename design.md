# UI/UX Art Direction — Premium English Learning Platform

Ты отвечаешь не просто за вёрстку, а за **полноценный визуальный дизайн продукта**.

Проект — современный сайт-тренажёр для изучения английского языка. Это не детское приложение, не школьный учебник и не очередной дешёвый EdTech SaaS.

Главная задача интерфейса:

> Пользователь должен открыть сайт и сразу почувствовать: «Это серьёзный, качественный и дорогой продукт, которым приятно пользоваться каждый день».

## 1. Главный визуальный принцип

Создай визуальный язык уровня дорогого современного digital-продукта.

Ориентиры по ощущениям:

* premium
* sophisticated
* calm
* интеллектуальный
* современный
* минималистичный
* уверенный
* editorial
* tactile
* немного cinematic

Не копируй конкретные сайты или бренды. Используй только общие визуальные принципы.

Сайт должен выглядеть так, будто над ним работала сильная команда product designer + art director + frontend engineer.

---

# 2. Чего категорически НЕ делать

Избегай типичного AI-generated SaaS дизайна.

### Нельзя:

* фиолетовые/синие градиенты на белом фоне
* огромные rounded cards повсюду
* одинаковые карточки в сетке 3×3
* чрезмерно закруглённые элементы
* стеклянный glassmorphism ради glassmorphism
* неон
* кислотные цвета
* чрезмерные тени
* визуальный шум
* огромные надписи без композиционной причины
* emoji как основной элемент UI
* иллюстрации в стиле корпоративных стоков
* интерфейс похожий на Duolingo
* интерфейс похожий на школьное приложение
* визуальный стиль «AI startup landing page 2024»
* бессмысленные декоративные элементы
* каждый блок помещать в отдельную карточку
* одинаковые размеры всех элементов
* чрезмерное количество border-radius
* стандартный Bootstrap/Tailwind-looking интерфейс
* ощущение админки

Особенно избегай ощущения:

> «Это сгенерировал AI из запроса "modern education website".»

---

# 3. Визуальная концепция

Представь продукт на пересечении:

**premium editorial magazine + modern productivity app + language laboratory.**

Интерфейс должен ощущаться скорее как дорогой цифровой инструмент для развития интеллекта, чем как «курс английского».

Можно использовать:

* глубокий тёмный основной фон
* тёплые нейтральные оттенки
* off-white
* graphite
* charcoal
* muted beige
* приглушённые акцентные цвета
* один выразительный accent color
* тонкие линии
* аккуратную типографику
* крупную типографическую иерархию
* много воздуха
* асимметричные композиции
* subtle gradients только там, где они действительно нужны
* очень мягкие hover-анимации
* деликатную глубину интерфейса

Цветовая палитра должна выглядеть дорого даже без изображений.

Не используй много цветов одновременно.

Правило:

**neutral base + 1 primary accent + semantic colors.**

---

# 4. Типографика

Типографика — один из главных элементов дизайна.

Не используй шрифт просто потому, что он является стандартом.

Подбери современную пару шрифтов:

* основной UI font
* выразительный display/editorial font для крупных заголовков

Можно рассмотреть современные grotesk / neo-grotesk / humanist sans-serif и аккуратный serif для editorial accent.

Но шрифты должны:

* отлично читаться на русском
* отлично читаться на английском
* иметь хорошие веса
* работать на desktop и mobile
* выглядеть дорого
* иметь хороший rhythm

Иерархия должна быть очевидной:

* Display
* H1
* H2
* H3
* body
* secondary
* caption
* metadata

Не делай все тексты одинаковыми по размеру и весу.

---

# 5. Общая композиция

Используй полноценную дизайн-систему.

Определи:

* spacing scale
* typography scale
* border radius scale
* shadows
* borders
* colors
* transitions
* container widths
* breakpoints
* z-index hierarchy

Не придумывай значения хаотично для каждого элемента.

Создай единый визуальный язык.

Например:

```text
spacing:
4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128

radius:
small / medium / large

borders:
subtle / default / strong

motion:
fast / normal / slow
```

Конкретные значения выбери сам исходя из дизайна.

---

# 6. Layout

Не строй весь сайт из одинаковых карточек.

Используй разные типы композиции:

* editorial sections
* split layouts
* asymmetric grids
* horizontal progress areas
* large typographic sections
* compact utility panels
* floating controls
* full-width sections
* focused exercise areas

Карточка должна появляться только тогда, когда она действительно помогает структурировать информацию.

---

# 7. Главная страница

Главная страница должна сразу объяснять продукт.

Но не превращай её в стандартный marketing landing page.

Hero должен быть визуально сильным.

Пример направления:

Большой спокойный заголовок:

> Build English into a skill.

или аналогичный сильный copy.

Небольшой supporting text.

CTA.

Рядом или ниже — **реальный фрагмент интерфейса тренажёра**, а не абстрактная иллюстрация.

Пользователь должен увидеть:

* упражнение
* прогресс
* слова
* статистику
* streak
* уровень
* небольшие элементы обучения

То есть уже в hero должно быть видно, **что это настоящий продукт**.

---

# 8. Dashboard

Dashboard — одна из самых важных страниц.

Он не должен выглядеть как корпоративная аналитическая панель.

Создай ощущение персонального рабочего пространства.

Например:

```text
Good evening, Alex.

Your English
B1 · 64% → B2

[ Continue session ]

Today
────────────────────────

Vocabulary        18 / 20
Grammar            7 / 10
Listening          12 min
Review             23 words

────────────────────────

Current course
████████████░░░  78%

Next:
Conditionals
```

Но не копируй этот layout буквально.

Главная идея:

**минимум визуального шума + максимум ощущения прогресса.**

---

# 9. Exercise / Training UI

Экран упражнения должен быть особенно хорошо продуман.

Пользователь должен концентрироваться на одном действии.

Не показывай десяток панелей одновременно.

Приоритет:

1. текущая задача
2. контекст
3. ответ пользователя
4. feedback
5. progress

Например:

```text
GRAMMAR
CONDITIONALS

If I ___ more time,
I would travel more.

          [ had ]

────────────────────

Question 07 / 20

██████████████░░░
```

После ответа:

* правильный ответ
* краткое объяснение
* пример
* возможность продолжить

Feedback должен ощущаться приятно.

Не превращай ошибки в красный warning UI.

Ошибка — часть обучения.

---

# 10. Vocabulary

Экран словаря должен ощущаться как инструмент, а не список карточек.

Покажи:

* word
* pronunciation
* meaning
* examples
* part of speech
* familiarity
* review status

Используй хорошую типографику.

Слово должно быть визуальным центром.

---

# 11. Progress

Прогресс пользователя должен быть визуально интересным.

Не используй только:

```text
████████ 80%
```

Можно использовать:

* timeline
* skill map
* progression line
* milestones
* level indicators
* activity heatmap
* subtle charts

Но избегай ощущения бухгалтерской аналитики.

Пользователь должен понимать:

> «Я реально становлюсь лучше».

---

# 12. Navigation

Navigation должна быть очень чистой.

Не перегружай sidebar.

Основные разделы могут быть примерно такими:

* Learn
* Practice
* Vocabulary
* Progress
* Review

Profile/settings — отдельно.

Используй хорошие iconography.

Иконки должны быть:

* тонкими
* консистентными
* минималистичными

Не смешивай разные icon sets.

---

# 13. Motion design

Анимации обязательны, но они должны быть незаметными.

Не делай:

* flashy transitions
* excessive bouncing
* постоянные scale animations
* анимацию каждого элемента при загрузке

Используй:

* subtle fade
* slight translate
* smooth progress transitions
* hover states
* micro-interactions
* pleasant button feedback
* exercise answer transitions

Главный принцип:

> Animation should communicate state, not demand attention.

---

# 14. Состояния интерфейса

Каждый интерактивный элемент должен иметь продуманные состояния:

* default
* hover
* active
* focus
* disabled
* loading
* success
* error
* selected

Особенно важно:

* keyboard focus
* accessibility
* forms
* exercise answers

Не допускай ситуации, когда UI красиво выглядит только в default state.

---

# 15. Responsive

Desktop-first можно использовать как основу, но mobile нельзя делать «после».

Проект должен хорошо работать на:

* desktop
* laptop
* tablet
* mobile

На мобильном интерфейс должен перестраиваться логически, а не просто уменьшаться.

Особенно внимательно проработай:

* navigation
* exercise screen
* typography
* buttons
* progress
* vocabulary
* dashboard

---

# 16. Accessibility

Дизайн должен быть красивым, но не в ущерб usability.

Обязательно:

* хороший contrast
* visible focus states
* keyboard navigation
* readable font sizes
* достаточные hit areas
* semantic HTML
* aria-label там, где необходимо
* reduced-motion support

Не используй низкоконтрастный серый текст только ради эстетики.

---

# 17. Frontend implementation

При реализации:

* используй существующий стек проекта
* не меняй архитектуру без необходимости
* переиспользуй существующие компоненты
* создавай reusable UI primitives
* избегай огромных компонентов
* не дублируй стили
* держи дизайн-систему централизованной

Если проект использует Tailwind — создай coherent design tokens и используй их последовательно.

Если используется CSS — используй CSS variables.

Не пиши:

```css
margin-left: 17px;
margin-top: 23px;
padding: 13px;
```

в каждом компоненте отдельно.

Должна существовать система.

# 21. Важнейшее правило

Не пытайся сделать сайт «красивым» за счёт количества визуальных эффектов.

Дорогой дизайн достигается через:

**типографику + spacing + композицию + цвет + hierarchy + consistency + restraint.**

Если сомневаешься между двумя вариантами:

**выбирай более спокойный.**

Если элемент можно убрать без потери функциональности:

**убери его.**

Если весь экран пытается привлечь внимание:

**значит, ничего не привлекает внимание.**

# 22. Перед реализацией

Сначала самостоятельно проанализируй существующий проект.

Определи:

* текущую архитектуру
* существующие страницы
* существующие компоненты
* используемый UI stack
* routing
* состояние приложения
* существующие design tokens
* что можно переиспользовать
* что необходимо переработать

Не переписывай backend ради визуального изменения.

Не ломай существующую функциональность.

---

# 23. Процесс работы

Работай как senior product designer + senior frontend engineer.

Перед изменениями:

1. Изучи проект.
2. Определи существующую структуру.
3. Сформируй визуальную концепцию.
4. Определи design tokens.
5. Определи typography system.
6. Определи основные layout patterns.
7. Затем начинай реализацию.

После реализации:

1. Проверь все основные страницы.
2. Проверь desktop.
3. Проверь mobile.
4. Проверь hover/focus/active states.
5. Проверь визуальную консистентность.
6. Удали лишние элементы.
7. Проверь, нет ли признаков generic AI-generated UI.
8. Исправь всё, что выглядит дёшево, шаблонно или перегруженно.

---

# 24. Критерий качества

Представь, что этот продукт завтра увидит пользователь, который платит за курс $100–300.

Он должен подумать:

> «Да, я понимаю, за что здесь плачу».

Сайт должен вызывать желание:

**остаться → попробовать упражнение → пройти урок → вернуться завтра.**

Не делай просто красивый landing page.

Создай ощущение **настоящего premium learning product**.

Главная цель:

> **Make learning English feel like using a beautifully designed instrument.**
